# Changelog

## 0.2.2 (2026-10-28)

Additions from the prior-art follow-up; nothing here changes what an existing call returns.

- **Patch TOCs.** `toc::flags` names the flags word's bits (`HAS_BASE_BUNDLES` 1, `HAS_BASE_CHUNKS` 2, `HUFFMAN_NAMES` 4); `Toc::has_base_bundles` / `has_base_chunks`; `toc::merge(base, patch)` gives the TOC the game sees (the base's bundles and chunks the patch does not name, then the patch's); `Source::merged_toc(rel)` reads it from a mod folder over the base game's `Data`. 167 of the 213 TOCs of the 82 installed mod folders set both bits (46 hold 0): 153 have a stock base TOC (all 5,990 of their bundles replace a base bundle, 161,186 of 164,345 chunks override one), 14 are superbundles the mod adds. Removed bundles, compact 3-word chunk records and bundles outside the TOC occur in none of the 213 mod TOCs or 23 stock TOCs, so they are still refused.
- **`layout` module.** `layout.toc` typed (`superBundles`, `fs`, `head`, `platform`, `installChunks` with `id`, `name`, `installBundle`, `persistentIndex`, `superbundles`, `requiredChunks`, `alwaysInstalled`, `installGroups`, `excludedSuperbundles`, `settings.bundleFormat`), written back byte for byte; `Folder::layout`; `Folder::open` finds an install chunk's directory by `installBundle` when `name` is absent.
- **`bundle::ChunkMeta`.** The typed rows of a manifest's `chunkMeta` (`h64`; no `meta`, `firstMip`, or `container` with the six `BundleMetric`s): `read_chunk_meta`, `write_chunk_meta`, `Manifest::chunk_meta`. All 239,810 stock rows read and write back byte for byte.
- **EBX enumerations.** `Document::enum_members` / `enum_member` name the member of an enumeration value from the document's own reflection (3,368,509 of 3,368,510 stock values name one). `Value::Int` is unchanged.
- **`names::GuidNames`.** A table from an EBX document's file GUID to its name, built bundle by bundle (`add_bundle`); `Document::array_data_offset` finds an array's elements from its slot.
- **MeshSet enumerations.** `meshset::MeshType` (header byte 0x7c: rigid 46,977, skinned 296, composite 485 MeshSets), `PrimitiveType` (section byte 0x1f; triangle list in all 300,875 sections), `category` (the order of the five section lists), `set_flags` and `lod_flags` (the bits the data names), with `MeshSet::mesh_type`, `layout_flags`, `Lod::flags`, `Section::primitive_type`.
- **CAS.** Codec 9 (LZ4, one raw LZ4 block to the block's decoded size) decodes; codec 0x0f (Zstandard) is refused naming the codec and the initfs dictionary it may need. No block of the stock data or of the 82 mod folders (11.5 million headers) uses either.

## 0.2.1 (2026-10-27)

- `listing::TYPE_NAMES` names eight more resource types, matched by hash against the ids in the stock manifests (47 ids occur in 428,211 resource entries; 26 are named now): `PhysicsResource` `0x41759364` (33,277 entries), `OccluderMesh` `0x30b4a553` (442), `LayerGraphs` `0xde540c59` (22), `BundleRefTableResource` `0x428ec9d4` (8), `VisualTerrain` `0x1ca38e06`, `TerrainStreamingTree` `0x22fe8ac8` and `TerrainDecals` `0x15e1f32e` (4 each), `AtlasTexture` `0x957c32b1` (3). `resource_type_name` returns them (it returned `None`).
- `meshset` documentation: `Section::flags` takes 15 values in the 300,875 stock sections and does not identify the section list a section is in; `MeshSet::tail` is the geometry (vertex bytes, index bytes and four zero bytes) of the one LOD whose chunk GUID is all zero. No code change.

## 0.2.0 (2026-10-27)

Readings corrected against the stock install (every TOC, bundle manifest, EBX payload, depot and texture header of build 20260929 read). Breaking.

- **EBX 64-bit integers: `FieldType::Int64` is code 0x11 and `FieldType::UInt64` code 0x12** (they were the other way round). The game's own field names decide it (`CompareInt64EntityData.A` is code 0x11, `CompareUint64EntityData.A` code 0x12; none of 291 fields named for their signedness disagrees). Values of the 65 fields of code 0x12 now read as `Value::UInt` (17,750 of 77,112 have the top bit set and used to read negative) and the 12 fields of code 0x11 as `Value::Int`; written bytes do not change.
- **`TypeRef` names a slot of the EFIX type list, not an entry of the reflection table.** `TypeRef::descriptor` is replaced by `TypeRef::fixup_type` (the slot, `encoded >> 2`); `Document::type_ref_target` and `Document::fixup_type_target` find the reflected type of a slot by GUID and signature (`None` for the 499,474 of 513,119 stock references whose type the document does not reflect). Read as a reflection index (the old reading) 511,607 of 512,711 stock references named another type or none. `TypeRef::with_fixup_type` re-points a reference. `Carrier` now moves a type reference to the slot of the same type in the target's EFIX list, adding the type there if it has none, and no longer needs the target to reflect it; the writer refuses a reference past the list.
- **EBX floats keep their bits.** The writer wrote nothing for a NaN or an infinity (213 stock documents, 1,784 NaNs and one infinity, were refused); both are now read and written as stored, a NaN's payload and sign included. Every one of the 328,015 stock payloads is written again without a refusal and reads back to the same values (floats compared by bits). A finite value an `f32` field cannot hold is still refused.
- `depot::params` reads parameter type `0x566e2dd0` (one byte an element): the 732 stock material entries (95 blocks) it refused now parse; all 64,105 blocks of the 2,473 depots parse to their last byte.
- `cas::blocks` refuses a block whose flags nibble (the high four bits of header byte 5) is not 7. It is 7 in all 1,001,300 stock block headers and in all 1,535,187 blocks of the 82 mod folders installed beside them (ReSkate Studio maps among them); the writer already emitted `0x70`.
- `bundle::Asset::size` of a chunk is its `lsize`, the decoded size of the stored range, not `(loff & 0xFFFF) | lsize` (equal on every stock row, 239,810); `Asset::chunk_size()` is `loff + lsize`, the whole chunk (equal to the TOC chunk table's decoded size on all 40,504 stock rows with a nonzero `loff`).
- `texture::TextureHeader` names its fields: `unknown_00` is `mip_block_offsets: [u32; 2]` (the physical offsets of the 64 KiB blocks holding mips 1 and 2: right in all 39,632 stock headers whose chunk is in its TOC and where they are not both zero), `unknown_10` is `pool_id` (0 in every texture), `unknown_78` is `name_hash` (the djb2-xor of the lowercase resource name, all 61,618 stock texture headers), `unknown_7c` and `unknown_80`; `texture::flags` names the bits stock textures set. Bytes read and written are the same.
